# Своя тема

> Подключайте собственные Vue-компоненты, страницы и layouts из каталога `.docs/`,
> чтобы расширить приложение undocs — лендинг, кастомные секции или полностью
> свою оболочку документации.

Большинству сайтов документации достаточно Markdown и конфига. Но когда нужен
свой лендинг, компонент в Markdown или новый layout страницы, undocs позволяет
проекту документации поставлять свой Vue. Положите каталог `.docs/` рядом с
Markdown — компоненты, страницы и layouts подхватятся работающим приложением.

## Каталог `.docs/`

Создайте папку `.docs/` рядом с Markdown. undocs находит три особых
подкаталога:

```
my-docs/
  .config/
    docs.yaml          # your site config
  .docs/               # ← the theme layer
    components/        # Vue components (usable from Markdown + your pages)
    pages/             # file-based routes, layered over the built-ins
    layouts/           # named layouts a page can select
    public/            # static assets served at the site root
  1.guide/
    1.index.md         # your Markdown content
```

Всё под `.docs/{components,pages,layouts}` компилируется в приложение на этапе
сборки. `.docs/public/` отдаётся как статика. Любая другая папка (например,
`utils/` для общих хелперов) — обычный исходник, который вы импортируете
относительным путём.

::note
`.docs/` отслеживается в dev — добавление или удаление компонента, страницы
или layout вызывает перезагрузку, а правка горячо обновляется на месте.
::

## Импорт внутренностей undocs

undocs отдаёт свой исходный код как публичный subpath-экспорт, поэтому файлы
темы импортируют Vue, composables undocs, роутер и компоненты undocs по пути
`undocs/src/app/*`:

```vue [.docs/components/Hello.vue]
<script setup lang="ts">
import { ref } from "vue";
import Button from "undocs/src/app/components/ui/Button.vue";
import Icon from "undocs/src/app/components/global/Icon.vue";

const count = ref(0);
</script>

<template>
  <Button color="primary" @click="count++">
    <Icon name="i-lucide-plus" /> Clicked {{ count }}
  </Button>
</template>
```

::important
**Автоимпортов нет**. Каждый файл `.docs/**` импортирует реактивность Vue,
composables undocs, роутер и компоненты **явно**. Так задумано — ничего не
попадает в область видимости магически.
::

Корни импорта, которыми вы будете пользоваться:

| Импорт из                       | Что там                                                      |
| ------------------------------- | ------------------------------------------------------------ |
| `undocs/src/app/components/**`  | UI, layout, блоки и docs-компоненты undocs                   |
| `undocs/src/app/content/**`     | рендерер Markdown и prose-компоненты                         |
| `undocs/src/app/composables/**` | `useAsyncData`, `useAppConfig`, `usePageSEO`, `queryPage`, … |
| `undocs/src/app/router`         | `useRoute`, `useRouter`, `AppLink`                           |

### Типы в редакторе

Поскольку экспорт указывает на реальный исходник, проверка типов и подсказки
редактора работают, как только у `.vue`-импортов есть ambient-объявление
модуля. Добавьте shim в проект документации:

```ts [.docs/shims.d.ts]
declare module "*.vue" {
  import type { DefineComponent } from "vue";
  const component: DefineComponent<{}, {}, any>;
  export default component;
}
```

## Компоненты

Любой `.vue` файл в `.docs/components/` загружается и регистрируется **дважды**:

- в **рендерер Markdown**, чтобы его можно было вызывать из любого `.md` по
  PascalCase-имени или kebab-case-тегу;
- **глобально в приложении**, чтобы ваши страницы и layouts могли использовать
  его по имени без импорта.

Файл `TechCard.vue` регистрируется и как `TechCard`, и как `tech-card`.
Вложенные папки на имя не влияют — берётся только basename файла.

::note
Встроенные компоненты побеждают при конфликте имён. Файл `Alert.vue` или
`Button.vue` не перекроет собственные компоненты undocs — выберите другое имя.
::

### Пример

```vue [.docs/components/TechCard.vue]
<script setup lang="ts">
import Icon from "undocs/src/app/components/global/Icon.vue";

defineProps<{ icon?: string; title?: string }>();
</script>

<template>
  <div class="rounded-xl border border-border bg-card p-6">
    <Icon v-if="icon" :name="icon" class="size-6 text-brand" />
    <h3 class="mt-3 font-semibold text-foreground">{{ title }}</h3>
    <p class="mt-1 text-sm text-muted-foreground"><slot /></p>
  </div>
</template>
```

Используйте из Markdown kebab-тегом. Props — в `{}`, тело блока — default slot:

```mdc
::tech-card{icon="i-lucide-rocket" title="Fast"}
Built on Vite and Nitro for instant HMR.
::
```

Или со своих страниц/layouts — по имени, без импорта:

```vue
<template>
  <TechCard icon="i-lucide-rocket" title="Fast">Built on Vite.</TechCard>
</template>
```

## Markdown-блоки и MDC

Рендерер Markdown undocs уже поставляет набор компонентов, доступных из любого
`.md` через синтаксис
[MDC](https://content.nuxt.com/docs/files/markdown#mdc-syntax) — код темы не
нужен:

| Блок            | Как вызвать                                                                                                  |
| --------------- | ------------------------------------------------------------------------------------------------------------ |
| Врезки          | `::note`, `::tip`, `::important`, `::warning`, `::caution`                                                   |
| Группа кода     | `::code-group` (или соседние fenced-блоки — см. [Преобразование контента](/ru/guide/content-transformation)) |
| Дерево кода     | `::code-tree`                                                                                                |
| Вкладки         | `::tabs` / `::tab`                                                                                           |
| Шаги            | `::steps` (или нумерованный список)                                                                          |
| Hero лендинга   | `::page-hero`                                                                                                |
| Секции лендинга | `::page-section`, `::page-feature`, `::page-card`                                                            |

Ваши `.docs/components/**` попадают в тот же реестр, поэтому тег `::my-block`
резолвится в ваш компонент (при конфликте всё ещё побеждают встроенные).

### Именованные слоты

Блок `#name` внутри контейнера мапится на соответствующий Vue **named slot**
компонента; всё остальное — default slot. Так `::page-hero` заполняет слоты
`title`, `description` и `links` из Markdown:

```mdc
::page-hero{orientation="horizontal"}
#title
Соберите [отличную]{.text-brand} документацию

#description
Публикуйте Markdown с лендингом, который выглядит как ваш продукт.

#links
:read-more{to="/ru/guide" title="Начать"}
::
```

То же работает для любого вашего компонента — блок `#footer` попадёт в
`<slot name="footer" />`.

### Асинхронным блокам нужен обёрточный `<Suspense>`

Блоки с данными `PageSponsors` и `PageContributors` делают fetch в setup,
поэтому напрямую в Markdown не регистрируются. Оберните такой блок тонким
компонентом `.docs` с локальным `<Suspense>`, чтобы он рендерился на сервере:

```vue [.docs/components/Sponsors.vue]
<script setup lang="ts">
import { Suspense } from "vue";
import PageSponsors from "undocs/src/app/components/blocks/PageSponsors.vue";
</script>

<template>
  <Suspense>
    <PageSponsors />
  </Suspense>
</template>
```

Затем используйте `::sponsors` в Markdown. (Данные спонсоров берутся из опции
`sponsors.api` в `docs.yaml`.)

## Страницы

Каждый `.vue` файл в `.docs/pages/` становится маршрутом, наложенным **поверх**
встроенных — страница пользователя всегда побеждает:

| Файл                           | Совпадает с                            |
| ------------------------------ | -------------------------------------- |
| `pages/index.vue`              | `/` — перекрывает лендинг по умолчанию |
| `pages/showcase.vue`           | `/showcase`                            |
| `pages/team/[id].vue`          | `/team/:anything`                      |
| `pages/examples/[...slug].vue` | `/examples` и всё ниже                 |

Параметры маршрута **не** извлекаются — читайте `route.path` напрямую, как
встроенная docs-страница:

```vue [.docs/pages/showcase.vue]
<script setup lang="ts">
import { useRoute } from "undocs/src/app/router";
import { queryPage, queryNavigation } from "undocs/src/app/composables/useContent";
import { useAsyncData } from "undocs/src/app/composables/useAsyncData";
import Page from "undocs/src/app/components/layout/Page.vue";
import PageHeader from "undocs/src/app/components/layout/PageHeader.vue";
import PageBody from "undocs/src/app/components/layout/PageBody.vue";
import MarkdownRenderer from "undocs/src/app/content/MarkdownRenderer";

const route = useRoute();

// Fetch content over the same `/api/docs/*` boundary your Markdown pages use.
const { data: page } = await useAsyncData(route.path, () => queryPage(route.path));
const { data: nav } = await useAsyncData("nav", () => queryNavigation());
</script>

<template>
  <Page>
    <PageHeader title="Showcase" />
    <PageBody>
      <MarkdownRenderer v-if="page" :value="page" />
    </PageBody>
  </Page>
</template>
```

::tip
`queryPage(path)` возвращает одну страницу (или `null` при промахе) с
отрендеренным body; `queryNavigation()` — дерево навигации. Оба — обычные
fetch к content API, поэтому чисто prerenderятся. Оборачивайте их в
`useAsyncData`, чтобы результат попал в payload и не перезапрашивался на
клиенте.
::

## Layouts и `definePageMeta`

`.vue` файл в `.docs/layouts/` — именованный layout, ключ — lower-cased
basename. Layout рендерит страницу через default `<slot />`:

```vue [.docs/layouts/marketing.vue]
<script setup lang="ts">
import Container from "undocs/src/app/components/Container.vue";
</script>

<template>
  <Container>
    <slot />
  </Container>
</template>
```

Страница выбирает layout через `definePageMeta`. undocs резолвит layout на
**сборке**, статически читая этот вызов, — layout известен до серверного
рендера. Значение `layout` пишите обычным строковым литералом. `title` и
`description` применяются в **runtime** через unhead:

```ts
definePageMeta({
  layout: "marketing",
  title: "Showcase",
  description: "Sites built with undocs.",
});
```

Поскольку автоимпортов нет, сделайте `definePageMeta` небольшим хелпером в теме
и импортируйте на каждой странице:

```ts [.docs/utils/definePageMeta.ts]
import { useSeoMeta } from "@unhead/vue";
import { usePageSEO } from "undocs/src/app/composables/usePageSEO";

export interface PageMeta {
  /** Resolved at build time by undocs; ignored at runtime. */
  layout?: string;
  title?: string;
  description?: string;
}

export function definePageMeta(meta: PageMeta): void {
  if (meta.title !== undefined) {
    usePageSEO({ title: meta.title, description: meta.description ?? "" });
  } else if (meta.description !== undefined) {
    useSeoMeta({ description: meta.description });
  }
}
```

::note
Runtime-хелпер намеренно игнорирует `layout`: `AppLayout` выбирает layout до
запуска `<script setup>` страницы, поэтому смена в runtime сломала бы
SSR/hydration. Единственный источник правды — статическое чтение на сборке.
::

Встроенные layouts — `docs` и `blog`. Файл `.docs/layouts/docs.vue` переопределяет
default docs layout для всего сайта.

## Стили

undocs использует [Tailwind v4](https://tailwindcss.com/) с дизайн-системой
[Geist](https://vercel.com/geist). Стилизуйте компоненты семантическими
токенами ниже — они резолвятся в палитру Geist и сами адаптируются к light/dark:

| Utility                                  | Для чего                                |
| ---------------------------------------- | --------------------------------------- |
| `text-foreground`                        | основной текст                          |
| `text-muted-foreground`                  | вторичный / приглушённый текст          |
| `text-brand`                             | акцентный текст (ваш `themeColor`)      |
| `bg-background`                          | фон страницы                            |
| `bg-card`                                | приподнятые поверхности / карточки      |
| `bg-muted`                               | мягкие заливки поверхностей             |
| `bg-accent`                              | заливки при hover                       |
| `bg-primary` + `text-primary-foreground` | высококонтрастная кнопка (чёрный/белый) |
| `border-border`                          | границы и разделители                   |
| `ring-ring`                              | focus rings                             |

::note
Geist **монохромный**: `text-primary` / `bg-primary` — почти чёрный на белом
и почти белый на чёрном, а не цвет вашей темы. Ваш `themeColor` живёт в
`text-brand` / `bg-brand`. Если нужен оттенок акцента проекта — берите `brand`.

По умолчанию `themeColor` — `mono`, поэтому `text-brand` совпадает с цветом
текста, пока вы не выберете hue — задайте [`themeColor`](/ru/config#themecolor)
как `blue`, `red`, `amber`, `green`, `teal`, `purple`, `pink` или любой CSS-цвет.
::

### Цвета статусов

Пять статусных ролей покрывают callouts, alerts и banners. Каждая — **тройка**:
текст, tint, на котором он лежит, и border — все три переключаются в dark mode
вместе, поэтому ни одной не нужен вариант `dark:`:

| Роль        | Utilities                                                          |
| ----------- | ------------------------------------------------------------------ |
| `info`      | `text-info` · `bg-info-tint` · `border-info-border`                |
| `success`   | `text-success` · `bg-success-tint` · `border-success-border`       |
| `warning`   | `text-warning` · `bg-warning-tint` · `border-warning-border`       |
| `danger`    | `text-danger` · `bg-danger-tint` · `border-danger-border`          |
| `important` | `text-important` · `bg-important-tint` · `border-important-border` |

```html
<div class="rounded-lg border border-warning-border bg-warning-tint px-4 py-3 text-warning">
  Heads up.
</div>
```

Каждая роль проходит WCAG AA на своём tint и на странице, в обоих режимах.

### Где может лежать brand-текст

`text-brand` рассчитан так, чтобы проходить AA на **странице**, на **карточке**
и на **размывке себя** (`bg-brand/10`, `bg-brand/15`) — и нигде больше. На
нейтральной заливке контраст падает ниже AA:

```html
<!-- ✅ an active / selected item -->
<a class="rounded-md bg-brand/10 px-3 text-brand">Guide</a>

<!-- ❌ measures ~3.9:1 -->
<a class="rounded-md bg-accent px-3 text-brand">Guide</a>
```

### Типографика и материалы

Шкала типа Geist доступна как `text-heading-{14,16,20,24,32}`,
`text-copy-{14,16}`, `text-label-12` и `text-button-{12,14,16}`; каждая задаёт
сразу font-size, line-height, letter-spacing и weight.

Elevation — `shadow-small` для поверхностей на странице и
`shadow-{tooltip,menu,modal}` для плавающих.

::warning
Имена классов Nuxt UI вроде `border-default`, `bg-elevated`, `text-default`,
`text-highlighted` и `text-dimmed` в undocs **не определены** — CSS не
генерируется, и они молча «ломаются» (нет границ, почти невидимый текст).
Используйте токены выше. Особенно: `text-muted` — цвет _поверхности_, как
текст он невидим — берите `text-muted-foreground`.
::

Tailwind автоматически сканирует ваши `.docs/**` компоненты, поэтому любой
utility-класс там генерируется.

```vue [.docs/components/TechCard.vue]
defineProps<{ icon?: string; title?: string }>();
</script>

<template>
  <div class="rounded-xl border border-border bg-card p-6">
    <Icon v-if="icon" :name="icon" class="size-6 text-brand" />
    <h3 class="mt-3 font-semibold text-foreground">{{ title }}</h3>
    <p class="mt-1 text-sm text-muted-foreground"><slot /></p>
  </div>
</template>
```

```vue [.docs/layouts/marketing.vue]
<script setup lang="ts">
import Container from "undocs/src/app/components/Container.vue";
</script>

<template>
  <Container>
    <slot />
  </Container>

```

```vue [.docs/pages/index.vue]
<script setup lang="ts">
import { definePageMeta } from "../utils/definePageMeta";

// `TechCard` is globally registered from `.docs/components` — no import needed.
definePageMeta({
  layout: "marketing",
  title: "Home",
  description: "A custom undocs landing page.",
});
</script>
```

```ts [.docs/utils/definePageMeta.ts]
import { useSeoMeta } from "@unhead/vue";
import { usePageSEO } from "undocs/src/app/composables/usePageSEO";

export function definePageMeta(meta: {
  layout?: string;
  title?: string;
  description?: string;
}): void {
  if (meta.title !== undefined) {
    usePageSEO({ title: meta.title, description: meta.description ?? "" });
  } else if (meta.description !== undefined) {
    useSeoMeta({ description: meta.description });
  }
}
```
