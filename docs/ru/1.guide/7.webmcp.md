# Браузерные агенты (WebMCP)

> Когда читатель спрашивает AI-ассистента браузера о вашем проекте,
> тот может искать по вашей документации так же, как сам читатель —
> вместо того чтобы угадывать.

AI-ассистенты переезжают прямо в браузер: сайдбары, расширения и встроенные
агенты, которые видят страницу, на которой находится читатель.
[WebMCP](https://webmachinelearning.github.io/webmcp/) — черновик веб-стандарта,
который позволяет странице отдавать такому агенту настоящие tools вместо того,
чтобы оставлять его скрейпить отрендеренный HTML.

Сайты undocs делают это из коробки. Для агента ваша документация — шесть
tools: поиск, список, чтение, сведения о проекте, текущая страница, навигация —
поэтому вопрос вроде _«как задеплоить это на Vercel?»_ получает ответ из ваших
реальных страниц, со ссылкой, по которой читатель может перейти.

Ставить и настраивать ничего не нужно.

## Что получает читатель

Допустим, кто-то открыл вашу документацию в браузере с агентом и спрашивает:

> «Есть ли поддержка своих тем, и где об этом почитать?»

Вместо ответа из того, что агент «помнит» о проекте, он:

1. вызывает `search_docs("custom theme")` — тот же индекс, что за <kbd>⌘K</kbd>,
2. получает совпавшие секции с превью и URL,
3. вызывает `read_page("/guide/custom-theme")` за полным Markdown,
4. отвечает по этому тексту и предлагает `navigate` туда.

Ответ опирается на страницу, которую вы реально написали, в версии, которую
вы реально выпустили.

## Tools

| Tool               | Что делает                                                                             |
| ------------------ | -------------------------------------------------------------------------------------- |
| `search_docs`      | Полнотекстовый поиск по всем страницам и заголовкам. Возвращает titles, previews и URL |
| `list_pages`       | Все страницы в порядке навигации, с path и description — оглавление                    |
| `read_page`        | Markdown-исходник одной страницы. Длинные приходят кусками с cursor для продолжения    |
| `get_current_page` | Страница, которую читатель смотрит сейчас, плюс outline заголовков                     |
| `get_project_info` | Репозиторий, issues, releases, соцссылки, бандлы `llms.txt` и versions                 |
| `navigate`         | Открывает страницу во вкладке читателя, опционально прокручивая к заголовку            |

Каждый tool — тонкая обёртка над тем, что страница уже умеет. `search_docs`
ходит в тот же индекс MiniSearch, что и command palette — включая fallback
strict → fuzzy — а `read_page` возвращает тот же Markdown, на который указывает
`/llms.txt`. Агент ищет ровно то же, что и посетитель: второго индекса нет,
синхронизировать нечего.

Результаты — структурированные данные. Поисковый hit выглядит так:

```json
{
  "title": "Custom Theme",
  "breadcrumb": "Guide > Custom Theme",
  "path": "/guide/custom-theme",
  "url": "https://docs.example.com/guide/custom-theme#tokens",
  "preview": "Override the design tokens in your own CSS…"
}
```

Два tool, которые отвечают **прозой** — `search_docs` и `read_page` — используют
форму результата MCP: текст в блоке `content`, а поля выше — рядом в
`structuredContent`. Браузер отдаёт агенту return value tool как JSON, поэтому
страница Markdown в обычном поле пришла бы с литеральным `\n` на каждый перевод
строки и обратным слэшем перед каждой кавычкой. Так MCP-aware клиент разворачивает
ответ, и модель читает вашу страницу как страницу.

Длинная страница ограничена 40 000 символами за вызов. Агент с меньшим контекстом
может передать `maxLength` и брать мельче, шагая тем же cursor `nextOffset`.

Каждый результат страницы также несёт `markdownUrl` (исходник `/raw/*.md`) и
`editUrl` (ссылка «edit this page» на GitHub), чтобы агент мог процитировать
страницу дословно или отправить контрибьютора прямо в файл. У сгенерированных
маршрутов — лендинг и листинг блога — Markdown нет, поэтому эти поля просто
опускаются, а не указывают на URL с 404.

Агенты приходят со старыми ссылками — URL из чата месячной давности, вставленный
путь, страница, которую вы перенесли два релиза назад. Поэтому `read_page` и
`navigate` следуют `redirects` из `.config/docs` так же, как браузер посетителя:
запросите перенесённый путь — tool ответит страницей, куда он переехал, отметив
исходный путь в `redirectedFrom`. Редирект за пределы сайта
(`/changelog` → ваши GitHub releases) отдаётся как внешний URL, а не как
страница, которую «не удалось загрузить».

`get_project_info` закрывает остальное: где лежит исходник, куда завести баг,
лента релизов, ссылки сообщества и бандлы `llms.txt` для агента, которому
удобнее проглотить весь корпус сразу. Всё читается из `.config/docs` теми же
соглашениями, что рисуют header и footer, — агент и посетитель никогда не видят
разные ссылки.

## Читатель остаётся за рулём

Пять из шести tools только читают. `navigate` — единственный, что меняет то,
что видит читатель, и он так помечен: воспитанный агент спросит, прежде чем
кого-то перекинуть. Он также отвергает пути, которые не являются реальными
маршрутами — галлюцинированная ссылка не выбросит читателя на 404.

Назад приходит ваш собственный контент: ваши страницы, ваша навигация и ваш
`.config/docs`, всё из одного репозитория, из которого собран сайт. Поэтому
ничего не помечается как untrusted — этот маркер для tool, тянущего то, чем
автор страницы не управляет; вешать его на каждый результат здесь значило бы
учить агента его игнорировать.

## Как попробовать

WebMCP ещё ранний: нативный `document.modelContext` есть только в браузерах,
реализующих черновик, и только в secure context (HTTPS или `localhost`).
Ждать этого — почти никогда не иметь живых tools, поэтому undocs также
поставляет **polyfill** — небольшой порт
[reference polyfill Google](https://github.com/GoogleChromeLabs/webmcp-tools/blob/main/demos/shared/webmcp-polyfill.js),
под который сегодня пишут агенты, расширения и инспекторы. Он ставится только
когда у браузера своего нет; настоящая реализация всегда побеждает.

Tools в любом случае живут в отдельном lazy-чанке. За polyfill он не
загружается, пока агент впервые не запросит tools, — посетитель без агента
скачивает только polyfill (меньше килобайта gzip) и больше ничего.

Чтобы проверить, зарегистрировались ли tools, откройте консоль на сайте:

```js
await document.modelContext.getTools(); // → the six docs tools

// `executeTool` is the polyfill's own (a native browser calls tools itself):
await document.modelContext.executeTool("search_docs", { query: "deploy" });
```

> [!TIP]
> Не каждый агент говорит на WebMCP, и некоторые никогда не будут. Ваша
> документация также публикуется как [`/llms.txt`](/llms.txt) и `/llms-full.txt` —
> plain-text бандлы, которые может прочитать любая модель, — так что агенты
> вне браузера тоже покрыты.

## Как выключить

```ts [.config/docs.ts]
export default {
  webmcp: false,
};
```

Polyfill не ставится, ничего не регистрируется, чанк никогда не загружается.
